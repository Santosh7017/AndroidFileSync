Run `python3 AndroidFileSync/ConnectionTests/run.py --listing` for folder-listing regressions. These exercise the production ADB reader with simulated empty and permission-denied Downloads listings, recovery through find and the all-files provider, progressive results, non-media files, Unicode names, nested paths, and preserving access errors when recovery fails. They contact no phones or real ADB servers.

Run `python3 AndroidFileSync/ConnectionTests/run.py --pairing` for the pairing regressions alone.

Run `python3 AndroidFileSync/ConnectionTests/run.py --recognized` for recognized-device actions. These checks cover identity-matched manual connection, duplicate clicks, automatic progress, saved-name and session-cache removal, cancellation during verification, failure feedback, shutdown, rejecting remembered transports across app sessions, showing removed phones as new, and recognizing them again only through a new explicit connection.

The harness compiles the production connection managers, discovery view model, and process runner, substituting in-memory preferences and a simulated server-availability probe. It uses a fake ADB executable in a temporary directory. It does not connect to phones, start real ADB servers, or read/write the app's preferences.

QR regressions cover partial native discovery hiding the matching ADB service, partial native/ADB snapshots requiring DNS-SD fallback, unrelated active devices, reused pairing ports, verified post-pair connection, native-only pairing, and cancellation while regenerating. They also reproduce repeated pairing status errors with a healthy daemon, verify bounded retries and stable progress, distinguish discovery timeouts from handshake failures, preserve QR credentials at the deadline, and protect shared servers. Confirmed daemon faults recover once. DNS-SD output is simulated without publishing services or accessing the network.

Run `python3 ConnectionTests/run_pairing_response.py` to verify the production pair-response reader against fragmented loopback replies. It handles the bundled ADB server's `OKAY` then `FAIL` framing, explicit success, initial service rejection, malformed/truncated responses, cancellation and deadlines. `--real-adb 56037` also tests a running bundled server against a closed loopback port; it contacts no phone. The fake-ADB pairing suite verifies that the response-reader retry exposes the real error while preserving the two-operation limit and the server's keys/connections.

The same tests verify that socket diagnostics use only new errors for the current target, exclude unrelated traffic and credentials, and survive daemon-log rotation. The fake-ADB suite checks that a closed pairing port gets fresh-address guidance and a denied QR connection gets macOS Local Network guidance, with no healthy-daemon restart.

Pairing regressions also reproduce macOS 27 reporting a denied UDP path while the Settings toggle is enabled: the first ADB handshake runs immediately, and UDP diagnostics cannot veto a successful TCP retry or QR connection. They check cancellation while diagnosing a failed attempt, UDP filtering with working TCP pairing, and macOS 27's ambiguous “No route to host” error. The native UDP check is substituted in this harness so it never sends UDP questions to the fixture phone addresses.

Run `python3 AndroidFileSync/ConnectionTests/run_packaging.py` from the repository root for the DMG workflow. It executes the production script in an isolated directory with simulated Xcode, signing, and image tools. It checks certificate selection, rejection of missing/ad hoc identities, helper-before-app signing, Apple-anchor verification before packaging, rejection of failed signatures, and preservation of previous artifacts. It also verifies staging outside Documents, metadata-free copying, AppleDouble removal, cleaning immediately before the app signature, and retaining failed staging for diagnosis. It uses no certificates, keys, real DMG mounts, or app preferences; a real signed release still requires an Apple-issued certificate.

The QR suite also reproduces a native numeric address arriving during a slower DNS-SD hostname lookup. The hostname is simulated as unroutable; pairing must use the current numeric address and the matching pairing port, then verify the separate connect port. This regression fails before refreshing the native snapshot after the fallback finishes.

Run `python3 ConnectionTests/run_pairing_probe.py` from the project directory for the direct-reply mDNS fallback and native permission check. It tests compressed DNS records, malformed packets, matching the current QR service, real UDP traffic over loopback, deadlines, and cancellation. It verifies that the native check sends a valid mDNS question without opening TCP or requiring a reply, and distinguishes a privacy-denied path from a routing failure. It contacts no phones; loopback socket permission is required. The main harness also checks QR pairing when only this fallback finds the phone.

The direct probe also verifies exact SRV queries with no browse PTR, unicast to a discovered phone address, split SRV/A replies with a follow-up address query, zero-ID responses, pairing-port rotation, and TTL-zero goodbyes. The real Bonjour test covers starting the exact QR query before publication, resolving without a browse record, restoring it across a network refresh, and stopping it when the QR flow closes.

Coverage includes concurrent cold-daemon startup, avoiding a premature offline screen, bounded initial searches with quiet background discovery, serial-only preference migration, resolving current endpoints after restart, IP and port rotation, partial native discovery, rejecting stale results from both native and ADB snapshots, delivering a ready endpoint before an unresolved peer finishes, unchanged service names with changed SRV ports, discovery-cache invalidation, two-device toggle recovery, preserving pairing after connection refusal/timeouts, explicit authentication rejection, DHCP address reuse, manual connections without multicast, identity-based disconnect recovery and stale cleanup, mixed ADB servers, immediate shared-USB startup, authorization status, QR service matching, process cancellation, deadlines, large pipe output, and preventing ADB restarts during quit. Automatic recovery requires a current serial-matched connect advertisement; saved IPs and ports are never candidates. The deterministic SRV tests use a controlled NetService resolver with the production cache/delegates. Actual USB/Wi-Fi latency still requires device testing.

Run `python3 AndroidFileSync/ConnectionTests/run_quit.py` to test the production app delegate in AppKit's actual quit loop. This needs a logged-in macOS session, but opens no windows and substitutes preferences, managers, logs, and ADB. It checks normal cleanup, hung ADB commands, and an injected cleanup stall to verify the four-second overall deadline. It also verifies that app-owned children stop and Android Studio's daemon is preserved.

Run `python3 AndroidFileSync/ConnectionTests/run_discovery.py` to test the production continuous DNS-SD resolver against macOS Bonjour. It temporarily publishes one uniquely named local service using individual DNS records, changes its SRV port in place without removing/re-adding the service, rejects the old endpoint, and verifies that the new port arrives through a live callback within three seconds. It then removes the advertisement and stops discovery. It uses no phones, ADB, windows, or app preferences; access to the system Bonjour service is required.

Run `python3 AndroidFileSync/ConnectionTests/run_serial_discovery.py SERIAL [SERIAL ...]` to check the production serial-to-endpoint lookup against this Mac's real network discovery. It uses isolated preferences and logs, the bundled ADB, and native Bonjour. It prints current connect addresses without issuing pair, connect, disconnect, or shell commands. Access to local ADB and Bonjour is required; the app's private ADB server may be started if it is not running.

Connection latency regressions also cover a native-only advertisement surviving a slow first shell verification, publishing shared USB before an unrelated private server times out, choosing a ready transport over an offline previous owner, immediate authorization and transport-loss notifications through `adb track-devices`, idempotent watcher startup, ignoring detection results after monitoring stops, and avoiding reconnects when a healthy connection's liveness timestamp ages. These tests simulate phone timing; they do not measure physical USB or Wi-Fi latency.

Run `python3 ConnectionTests/run_tracking.py` from the AndroidFileSync project directory to verify that the bundled ADB streams device changes before its tracking process exits. This uses a temporary loopback fake daemon on an ephemeral port; it never contacts a phone or either of the app's normal ADB ports. Loopback socket permission is required.

The Bonjour test also uses a temporary raw mDNS publisher that silently changes its SRV port and replies with the new port only when queried. This verifies that refusal triggers `DNSServiceReconfirmRecord` and an actual network query. `python3 ConnectionTests/run_discovery.py --without-reconfirmation` runs the negative control: it must reproduce the stuck old port with cache reconfirmation disabled. Both tests remove their temporary records afterward. The fake-ADB harness also checks refused-port replacement during startup with a second remembered phone absent, and rejects an old ADB snapshot after a newer native port arrives.
